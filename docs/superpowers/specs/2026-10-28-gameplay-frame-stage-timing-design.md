# Gameplay frame stage timing

The user approved trying the frame-correlated stage timing described in the active gameplay investigation. Extend the existing Metal display-link capture and performance-log export so a slow frame can be separated into scene update/render, gameplay capture/projection, skin preparation/submission, BGA preparation/fullscreen output, bgfx submission, deferred scene work, and terminal persistence/authority stop. Record observed gameplay phases (preparing, active, paused, post-notes, ending), playback mode and selected skin. A frame that changes phase must retain both observations.

Use bounded, allocation-free application-worker scratch, activated only by a display-link token. Scoped elapsed timers accumulate inclusive durations and completion counts; nested stages are not additive. Publish the scratch once at frame end into the existing nonblocking ring, with the same token and CAMediaTime clock. Interrupted open scopes must be marked incomplete and cannot leak into a later frame. Disabled instrumentation must not call the clock. Preserve the existing timing-column prefix and append explicitly documented v2 metadata/stage columns. No per-frame logging, file I/O, waits, scene behavior, pacing or input-worker changes.

Approach selected as an implementation detail: extend the existing recorder. A separate profiler cannot be joined reliably to the supplied logs; a new per-stage concurrent ring adds unnecessary contention. Fixed application-thread scratch provides the needed correlation with one ring publication per frame. This change records elapsed intervals, not CPU busy time, GPU per-pass time, or input latency.
