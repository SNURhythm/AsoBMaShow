안녕하세요, AsoBMaShow의 개발자 Violet입니다. AsoBMaShow에서 HorieYuuka님의 Be-Music Script 패키지 검색/다운로드 API를 무단으로 사용하여 피해를 입은 HorieYuuka님, 나아가 저의 잘못으로 인한 서버 중단 조치로부터 피해를 입은 BMS 커뮤니티 여러분들께 사과의 말씀을 드립니다.

# 무슨 일이 일어났는가
2026년 6월 14일, 저는 개인 이용 목적으로 개발하고 있었던 AsoBMaShow에 개인적으로 BMS를 편하게 다운로드 받기 위해, HorieYuuka님의 허가를 얻지 않은 채 서비스를 연동했습니다. 저는 외부 앱에서 해당 REST API를 이용해도 되는지에 대한 허락을 구하지 않고 무단으로 연동하였기에 개인적 이용도 정당하지 않았을 뿐더러, 공개 배포 전에도 해당 문제를 바로잡지 않았습니다. 그 결과 2026년 10월 3일 최초 공개 버전에 REST API 연동이 포함되었고, 기능 추가에만 급급하여 지난 실수를 되돌아보지 않은 저의 미숙함으로 인해 이 구현은 2026년 11월 1일까지 제거되지 않고 방치되었습니다. 허락을 구하지 않고 기능을 연동한 점, 이를 공개 배포 이후에도 바로잡지 않은 점에 대한 책임을 통감하고 있습니다.

2026년 10월 24일, HorieYuuka님께서는 REST API의 부정 사용을 확인하시고 임시적인 서버 중단과 함께 Cloudflare Turnstile, User Agent기반 필터링 등을 도입하여 REST API를 통한 자동 다운로드를 차단하는 기능을 도입하셨습니다. 무책임하게도 저는 2026년 11월 1일에야 REST API의 접근이 제한된 사실을 확인했습니다. 또한 HorieYuuka님의 서비스에서 BMS를 찾을 때, 접근 거부를 올바르게 처리하지 않고 다른 쿼리로 재시도할 수 있는 구현상의 문제점도 있었습니다. 이러한 동작을 면밀히 검토하지 않고 배포한 책임도 저에게 있습니다.

2026년 11월 1일, 저는 AsoBMaShow에 인앱 브라우저에서 BMS 패키지 파일을 다운로드 받으면 이를 인식하여 자동으로 라이브러리에 추가해주는 기능을 개발하였고, 이 과정에서 기존 다운로드 UI도 함께 개편하여 테스트하던 중, HorieYuuka님의 REST API가 차단되었다는 사실을 인지하게 되었습니다. 여기서 HorieYuuka님의 서비스와의 연동을 완전히 제거했어야 했지만, “유저가 직접 인앱 브라우저에서 다운로드 받는 건 문제가 없지 않을까”라는 안일한 생각으로 인앱 브라우저의 기본 즐겨찾기에 HorieYuuka님의 웹페이지를 추가하게 됩니다. 접근 제한을 인지한 시점에서 HorieYuuka님의 서비스 이용 방침을 재확인했어야 했으나, 그렇게 하지 않고 브라우저를 이용한 수동 다운로드 방식은 괜찮을 것이라고 임의로 판단한 잘못입니다.

이후 각종 사이트에서 인앱 브라우저 다운로드 기능을 테스트하던 중 HorieYuuka님의 사이트에서만 다운로드 버튼이 아무런 반응이 없는 것을 확인하고, 이러한 현상이 브라우저 호환성 문제로 인한 것이라고 잘못 판단했습니다. 당시 저는 HorieYuuka님이 AsoBMaShow를 대상으로 한 제한 조치를 추가하셨다는 점을 인지하지 못한 채 일반적인 브라우저 동작 및 식별 정보(User Agent)를 이용하지 않아서 다운로드가 작동하지 않는 것으로 착각했습니다. 마찬가지로 이 시점에서조차 HorieYuuka님의 입장을 확인하지 않은 잘못이 있습니다.

그러한 착각 하에, 저는 User Agent를 일반적인 브라우저가 사용하는 것으로 변경하기 위해 iOS의 User Agent에서 AsoBMaShow 표시를 제거하였고, Cloudflare Turnstile의 사람 감지 로직이 정상적으로 동작하는데 필요한 브라우저 기능을 허용했습니다. 이후 Android의 User Agent도 마찬가지로 WebView 표시를 제거하는 방향으로 수정했습니다. 이 과정에서 저는 HorieYuuka님의 REST API 연동을 완전히 제거했습니다.

접근 제한을 확인하고도 HorieYuuka님의 입장을 확인하지 않고 다운로드 방식을 사이트에 접속하여 수동으로 받는 방식으로 바꾸면 괜찮을 것이라고 임의로 판단한 점, 그 결과 HorieYuuka님의 차단 정책을 우회한 형태로 앱을 배포한 점 모두 저에게 책임이 있습니다.
해당 인앱 브라우저 기능은 2026년 11월 2일에 배포되었으며, 인앱 브라우저 연동도 원하지 않으신다는 입장을 2026년 11월 7일에 뒤늦게 인지하여 즉시 인앱 브라우저의 즐겨찾기에서 HorieYuuka님의 사이트를 제거한 후 배포하였습니다.

# 어째서 사과가 늦었는가
HorieYuuka님이 AsoBMaShow의 이름을 직접적으로 언급하지 않은 채 무단 연동에 대한 경고를 작성하신 것은 2026년 10월 24일, 그리고 해당 연동의 주체가 AsoBMaShow임을 밝히고 문제를 제기하신 것은 2026년 11월 2일입니다. 또한 2026년 11월 2일에는 X를 통해 DM까지도 보내주셨으나, 제가 팔로우 관계가 아닌 유저의 DM은 알림을 받지 않도록 설정해두고, HorieYuuka님의 X 포스트 및 디시인사이드 리듬게임 갤러리에 게시하신 글을 미처 확인하지 못한 채 2026년 11월 7일 지인의 제보로 뒤늦게 인지하게 되었습니다. 공개 소프트웨어의 개발자로서 공식 연락 창구와 메시지 요청을 지속적으로 확인할 책임이 있었음에도 불구하고 그러지 않은 것은 전적으로 저의 잘못입니다.

다만 연락을 늦게 확인한 것이 11월 1일에 API 차단을 인지하고도 HorieYuuka님께 문의하지 않은 저의 잘못을 결코 정당화하지는 못합니다.

2026년 11월 7일 HorieYuuka님의 연락을 인지한 즉시 개인적으로 문제의 발생 경위와 사과의 말씀을 드렸으나, 그 과정에서조차 사실관계를 잘못 설명한 부분이 있었습니다. 개인적으로 경위를 설명해 드릴 때 GingerRush 연동과 관련된 버그를 Codex를 이용하여 수정하던 중 HorieYuuka님의 REST API에 대한 User Agent가 함께 수정된 것으로 보인다는, 당시 기록을 면밀하게 확인하지 않고 단순 추측을 마치 사실 관계를 확인한 것처럼 전달해드렸습니다. 그러나 기억을 찬찬히 되짚어보고 관련 수정 기록을 확인한 결과, GingerRush 버그 수정 커밋에는 REST API에 대한 User Agent 변경이 포함되어 있지 않았으며, 실제로 변경된 것은 인앱 브라우저의 User Agent였다는 사실을 확인했습니다. 이에 2026년 11월 8일 잘못된 사실 관계 파악 정정 및 내용을 보충하여 사과문을 작성하였습니다. HorieYuuka님의 공개 승인을 거쳐 2026년 11월 9일에 모두가 볼 수 있는 곳에 게시하게 되었습니다.

검토 과정에서 다른 외부 서비스와의 연동 방식 또한 재확인했습니다. GingerRush, Konmai, Wriggle은 타 오픈소스 BMS 클라이언트 구현에서 사용하고 있는 API를 통해 곡 해시를 기반으로 다운로드하는 방식을 사용하고 있습니다. 다른 클라이언트의 구현을 참고하여 구현하였으나, 현재까지 확인한 공개 자료만으로는 해당 API가 모두가 사용할 수 있는 API인지, 해당 오픈소스 클라이언트들에 한해 제한적으로 허용된 것인지는 확인하지 못했습니다. 이에 따라 AsoBMaShow에서 사용해도 되는지에 대한 여부도 불명확함이 확인되었습니다. BMS Search는 외부 앱에서 사용할 수 있는 공개 API를 안내하고 있으나, AsoBMaShow에서는 해당 API를 거치지 않고 HTML 페이지에서 다운로드 링크를 직접 추출하고 있었습니다. 이러한 HTML 수집 방식에 관한 BMS Search측의 허용 여부는 확인하지 못했습니다. Bokutachi IR 연동의 경우 문서화된 공개 API를 사용하고 있으며, 공식 문서에서 외부 프로그램을 이용하여 IR에 점수를 송신하거나 랭킹을 조회하는 방법을 안내하고 있음을 확인했습니다.

# 앞으로 어떻게 할 것인가
우선 최대한 많은 AsoBMaShow의 사용자가 이번 사건의 경위와 개발자인 저의 잘못과 책임을 인지할 수 있도록, 앱 시작 화면의 잘 보이는 곳에 본 게시글을 확인할 수 있도록 하겠습니다.

또한 앞으로 비슷한 문제가 재발하지 않도록, 외부 서비스 연동 및 기존 연동 서비스의 확장 시 서비스의 이용 허가 범위를 면밀히 검토하고, 그 근거를 기록하도록 하겠습니다. 만일 이용 허가를 확인한 이후에도 기존 연동 서비스의 접근 제한이 확인되면, 즉시 연동을 중단한 후 허용 범위의 변동 등 서비스 운영 측의 입장을 재확인한 후 재개 여부를 결정하겠으며, 허용 여부를 재확인하기 전에 User Agent를 변경하거나, 지원 방식을 변경하는 등의 작업으로 서비스 이용을 지속하는 행위는 결코 하지 않겠습니다.

그 출발점으로, GingerRush, Konmai, Wriggle, BMS Search의 이용 허용 범위가 불명확한 지금, BMS 다운로드 기능과 인앱 브라우저 기능을 먼저 제거한 후 충분한 검토를 진행한 다음 이용 재개 여부를 결정하겠습니다.

피해 배상에 관해서 HorieYuuka님께 연락드린 결과, 금전적인 배상은 원하지 않고, 허락 없이 서비스를 이용한 경위 및 접근 제한 이후에도 다른 방식으로의 연동을 계속 지원한 이유에 대한 해명과 그에 대한 책임을 공개적으로 인정할 것을 요청하셨으며, 그에 따라 위의 조치를 이행하고 진행 상황을 공유하겠습니다.

다시 한번 허락 없이 서비스를 앱에 연동하고 접근 제한을 확인한 후에도 서비스의 허용 범위를 제 임의로 판단하여 방식을 변경하여 연동을 지속 지원한 점, 그리고 앞선 개인적인 사과에서 사실관계를 잘못 설명드린 점에 대해 HorieYuuka님께 사과드립니다. 그리고 정당한 방법으로 서비스를 이용하고 계셨으나 저로 인해 불편을 겪으신 BMS 커뮤니티 여러분들께도 고개 숙여 사과드립니다.
